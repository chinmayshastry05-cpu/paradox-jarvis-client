# TOCTOU audit (Phase 1)

Every string-path file open in the audited trees must go through the
descriptor helpers in `openjarvis.security.canonical_path`
(`open_within`, `read_bytes_within`, `open_for_write_within`,
`open_rdwr_within`) or carry an explicit `# TOCTOU-safe` /
`# TOCTOU-allowlisted: <reason>` marker. `tests/security/test_toctou_audit.py`
is the tripwire: it AST-scans the audited trees and fails on any
unmarked `open` / `read_text` / `write_text` / `read_bytes` /
`write_bytes` call.

## Why

A check-then-open sequence (`exists()` → `open()`, `stat()` →
`open()`, `resolve()` → `open()`) has a window where a symlink can be
swapped in: the check sees the real file, the open follows the link to
a victim. The descriptor helpers walk the path holding directory
descriptors, open with `O_NOFOLLOW`, then verify dev/ino against the
walk — a swapped file is refused, not followed. Writes open WITHOUT
`O_TRUNC` and ftruncate only the verified fd, so a swapped victim keeps
its bytes (regression test in `test_toctou_audit.py`).

## Audited trees

`src/openjarvis/tools/`, `src/openjarvis/agents/`,

| Site | Change |

| `tools/file_read.py`, `tools/file_write.py`, `tools/apply_patch.py` | Already used descriptor helpers on the primary path (Phase 0); Phase 1 classified the legacy fallbacks (see below). |

## Allowlisted (configured / fixed / content-addressed paths)

These paths are **not** tool arguments or user input. They are
constructor-injected config, fixed filenames under a configured dir,
operator-controlled env vars, or content-addressed names. Each site
carries a `# TOCTOU-allowlisted: <reason>` marker in the source.

## Legacy fallbacks (no boundary, no containment claimed)

When no boundary is configured AND the platform lacks descriptor
open, these tools fall back to a plain string open with an explicit
`# TOCTOU-allowlisted` marker stating that no containment is claimed:

- `tools/file_read.py` `_legacy_read`, `tools/file_write.py`
  `_legacy_write`, `tools/apply_patch.py` (fd-is-None branch),
  `tools/audio_tool.py` `_legacy_transcribe`,
  `tools/browser.py` screenshot, `tools/pdf_tool.py`,
  `tools/storage/ingest.py` `_read_text`/`_read_pdf` (boundary=None),
  `tools/image_tool.py`, `tools/skill_manage.py`.

On POSIX (the supported platform for descriptor open) the fallback is
not reached; the helper path is used. On a platform without
`O_NOFOLLOW`/`dir_fd`, a configured boundary is **refused** rather
than silently downgraded (fail-closed).

## Explicitly out of scope (honest boundaries)

- **SQLite DB opens** (`agents/manager.py`, `memory/store.py`,
  `connectors/store.py`, `sessions/`): `sqlite3` needs a path; it
  cannot take a descriptor. The DB path comes from config, not tool
  arguments. A symlink at the DB path would be followed by sqlite —
  this is a documented residual, not fixed in Phase 1.
- **Shell tools** (`tools/shell_exec.py`, `tools/docker_shell_exec.py`):
  `subprocess.run`, not file opens. File access by shell commands is
  governed by the confirmation gate + container, not descriptor
  containment.
- **`shutil.copy2` in `apply_patch.py`'s legacy backup branch**:
  string-path copy, only reached when no boundary is configured and
  the platform lacks descriptor open. No containment claimed there.
- **`task_id` in `agents/hybrid/_base.py`**: assumed system-generated.
  If a future caller passes user input as `task_id`, the write must be
  re-audited (the tripwire marker says so).
- **`subset_path` / `persona` / `agent_name`**: operator/config values.
  They are not validated for `..` — the threat model is operator-trusted
  config. If any of them becomes tool-argument-derived, re-audit.

## Verification

```bash
PYTHONPATH=src .venv/bin/python -m pytest tests/security/test_toctou_audit.py -q -p no:cacheprovider
```

Covers: tripwire (all opens classified), symlink-escape refusal for
audio / PDF / ingest / browser screenshot / image / skill_manage, and
the non-destructive-write regression (swapped victim keeps its bytes).
